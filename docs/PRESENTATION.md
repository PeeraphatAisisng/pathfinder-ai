# แนวการนำเสนอ PathFinder AI (ประมาณ 7–10 นาที)

## 1. เปิด (1 นาที)
- ปัญหา: “จะไปจาก A ถึง B ให้ดีที่สุดได้อย่างไร” — เจอใน Google Maps, หุ่นยนต์, เกม
- โปรเจกต์นี้: เว็บแอปที่ให้เห็นว่า AI แต่ละแบบ “คิด” หาเส้นทางต่างกันอย่างไร

## 2. แนวคิด (2 นาที) — เปิด README หัวข้อ 3
- ทุกอัลกอริทึมใช้โครงเดียวกับในชั้น: `waiting_list`, `came_from`, `current`
- ต่างกันแค่วิธีหยิบช่องถัดไป: Queue / Stack / Priority Queue
- อธิบาย g(n), h(n), f(n) = g(n) + h(n)

## 3. สาธิตสด (4 นาที)
1. **แผนที่โล่ง** → รัน BFS (กระจายเป็นวง) แล้ว A* (พุ่งเข้าหาเป้าหมาย)
2. **วาดกำแพงรูปตัว U** ครอบหน้าจุด S → รัน Greedy (ติดกับดัก ทางอ้อม) แล้ว A* (ได้ทางดีที่สุด)
3. **วาดโคลนขวางทาง** → BFS เดินฝ่าโคลน, UCS/A* เดินอ้อม → ชี้ว่า “ต้นทุนรวม” ต่างกัน
4. **กดเปรียบเทียบทั้งหมด** → อ่านตาราง: A* ได้ทางดีที่สุดเหมือน UCS แต่สำรวจน้อยกว่ามาก
5. **สร้างเขาวงกต** → รัน DFS ความเร็วช้า ให้เห็นการมุดลึกแล้วย้อนกลับ
6. (ทางเลือก) ลากจุด G ไปมา → เส้นทางคำนวณใหม่แบบสด

## 4. ผลและสรุป (1 นาที)
- BFS: ก้าวน้อยสุด แต่ไม่สนต้นทุน
- DFS: เร็วบางครั้ง แต่ทางอ้อม
- UCS: ต้นทุนต่ำสุดเสมอ แต่สำรวจเยอะ
- Greedy: เร็วสุด แต่ไม่รับประกันคำตอบ
- **A\*: ดีที่สุดทั้งสองด้าน** ถ้าฮิวริสติก admissible

## 5. คำถามที่อาจถูกถาม
- **ทำไม A\* ถึงได้ทางดีที่สุด?** — เพราะ h(n) ไม่เคยประเมินเกินระยะจริง (admissible) A* จึงไม่ข้ามทางที่ถูกกว่า
- **Manhattan กับ Euclidean ต่างกันอย่างไร?** — ทั้งคู่ admissible แต่ Manhattan ใกล้ระยะจริงมากกว่าเมื่อเดิน 4 ทิศ จึงสำรวจน้อยกว่า
- **ทำไม BFS ไม่ optimal เมื่อมีโคลน?** — BFS นับจำนวนก้าว ไม่นับต้นทุนของแต่ละช่อง
- **ตรวจความถูกต้องอย่างไร?** — มีชุดทดสอบ `npm test` สุ่ม 30 แผนที่ เทียบว่า A* ได้ต้นทุนเท่า UCS เสมอ
- **Priority Queue ทำงานอย่างไร?** — ใช้ Min-Heap ดึงค่าน้อยสุดได้ใน O(log n) (ใน Python ใช้ `heapq`)
