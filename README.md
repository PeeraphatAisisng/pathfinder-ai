## 3. แนวคิด AI ที่ใช้

ทุกอัลกอริทึมใช้โครงเดียวกับที่เรียนในชั้น ต่างกันแค่ **วิธีเลือกช่องถัดไปจาก `waiting_list`**

```
waiting_list = [S]            # ช่องที่รอสำรวจ (frontier)
came_from = {S: None}         # จำว่ามาจากไหน เพื่อย้อนหาเส้นทาง
while waiting_list:
    current = เลือกช่องหนึ่งออกจาก waiting_list   ← จุดที่แต่ละอัลกอริทึมต่างกัน
    if current == G: ย้อน came_from จาก G กลับไป S → ได้เส้นทาง
    for ช่องข้างเคียงที่ยังไม่เคยไป:
        came_from[ช่องนั้น] = current
        ใส่ช่องนั้นลง waiting_list
```

| อัลกอริทึม | waiting_list เป็น | เลือกช่องที่… | Optimal? |
|---|---|---|---|
| BFS | Queue | เข้ามาก่อน | ✔ เมื่อทุกช่องต้นทุนเท่ากัน |
| DFS | Stack | เข้ามาล่าสุด | ✘ |
| UCS | Priority Queue | g(n) น้อยสุด (ต้นทุนสะสม) | ✔ เสมอ |
| Greedy | Priority Queue | h(n) น้อยสุด (ใกล้เป้าหมาย) | ✘ |
| A* | Priority Queue | f(n) = g(n) + h(n) น้อยสุด | ✔ เมื่อ h ไม่ประเมินเกินจริง |

- **g(n)** = ต้นทุนจริงจากจุดเริ่มต้นถึงช่อง n (ช่องปกติ 1, โคลน 5)
- **h(n)** = ระยะ *ประมาณ* จากช่อง n ถึงเป้าหมาย
  - Manhattan `|Δแถว| + |Δคอลัมน์|` เหมาะกับการเดิน 4 ทิศ
  - Euclidean `√(Δแถว² + Δคอลัมน์²)` ประเมินต่ำกว่าเล็กน้อย จึงสำรวจมากกว่า Manhattan
- ฮิวริสติกทั้งสอง **admissible** (ไม่ประเมินเกินระยะจริง) เพราะทุกก้าวมีต้นทุนอย่างน้อย 1 → A* จึงได้ทางที่ดีที่สุดเสมอ

## 4. ผลการทดลอง

ผลจาก `python python/search_algorithms.py` บนแผนที่ตัวอย่างที่มีแนวโคลนขวางกลาง:

| อัลกอริทึม | ช่องที่สำรวจ | จำนวนก้าว | ต้นทุนรวม |
|---|---:|---:|---:|
| BFS | 146 | 24 | 28 |
| DFS | 25 | 24 | 28 |
| UCS | 147 | 26 | **26** |
| Greedy | 25 | 24 | 28 |
| **A\*** | **69** | 26 | **26** |

**สรุปผล**
- BFS ได้เส้นทาง *ก้าวน้อยสุด* แต่เดินฝ่าโคลน ต้นทุนจึงสูง เพราะ BFS ไม่รู้จักต้นทุน
- UCS และ A* เดินอ้อมโคลน ได้ **ต้นทุนต่ำสุด (26)**
- A* ได้คำตอบเท่า UCS แต่ **สำรวจน้อยกว่าครึ่ง** (69 vs 147) เพราะมี h(n) ช่วยชี้ทิศ
- Greedy เร็วที่สุด (สำรวจ 25 ช่อง) แต่ไม่รับประกันว่าจะได้ทางที่ดีที่สุด

ในเว็บ กดปุ่ม **“เปรียบเทียบทั้งหมด”** เพื่อดูผลแบบนี้บนแผนที่ใดก็ได้
